# Golden cross-check

This directory holds a corpus of test addresses (`corpus.json`) and this
library's output for each (`js-output.json`, generated by
`scripts/gen-golden-js.ts`). It's the practical half of the Phase 8 "golden
cross-check" described in `.planning/PLAN.md` §6.

## What actually runs, and what doesn't

**`scripts/gen-golden-js.ts` runs for real** — it's plain Node, no C++
needed:

```bash
pnpm --filter @piplup/libaddressinput build
node --experimental-strip-types scripts/gen-golden-js.ts
```

It builds a `PreloadSupplier` backed by a real `FetchSource` (the live
`chromium-i18n.appspot.com` endpoint — the same one Chromium's own build
uses) and, for each corpus entry, records `formatAddress()`, `normalize()`,
`validate()`, and `buildLayout()`'s output.

**A literal "build upstream's C++ library and diff its output" comparison
does not run in CI or in this repo's history** — it needs a C++ toolchain
(g++/clang, GYP, Ninja, RE2, GTest — see
`third_party/libaddressinput/cpp/README.md`'s `apt-get` list) that wasn't
available in the environment this was written in. If you have that
toolchain, see [Running the C++ side](#running-the-c-side-not-verified-here)
below — that part is scaffolded but genuinely unverified; treat it as a
starting point, not a working pipeline.

## An important architectural fact this run makes concrete

`formatAddress()` and `buildLayout()` are **synchronous** — by design (see
`.planning/PLAN.md` §6 Phases 3 and 6), they read only the bundled fallback
data (`packages/core/src/data/fallback.ts`, generated from
`testdata/countryinfo.txt` — see `DIVERGENCES.md`), never whatever a
`Supplier` fetched. Only `validate()` and `normalize()` take a `supplier`
and can see live-fetched data. So in `js-output.json`:

- `formatted`, `normalized`, and `layout` reflect the **bundled OSS
  fixture** for every entry, regardless of what's live in production —
  e.g. `US` addresses format without a comma (`"Mountain View CA 94043"`,
  not `"Mountain View, CA 94043"`) because that's what the fixture's `fmt`
  string says, even though the live endpoint returns a comma. This is
  exactly the divergence documented in `DIVERGENCES.md`, now visible
  directly in a real generated artifact instead of just asserted in a
  comment.
- `problems` reflects whatever the injected `Source` supplied — in this
  script, the live endpoint. Swap in a different `Source` (e.g. one backed
  by `testdata/countryinfo.txt`, like the tests use) to see `problems`
  computed from the bundled data too.

If you need `formatAddress()`/`buildLayout()` to reflect live/current data
rather than the bundled fixture, that's a real limitation of the current
design worth knowing, not just of this golden check — see
`DIVERGENCES.md`'s "What this means for you" section.

## Regenerating `js-output.json`

```bash
pnpm --filter @piplup/libaddressinput build
node --experimental-strip-types scripts/gen-golden-js.ts
git diff test/golden/js-output.json   # review what changed and why
```

Expect it to change when: the bundled fallback data is regenerated
(`scripts/gen-fallback.ts`), the corpus (`corpus.json`) changes, or the
live production data itself changes (affects only the `problems` field, per
above) — that last one means a byte-identical `js-output.json` isn't
guaranteed across re-runs even with no code changes, so don't treat an
unreviewed diff here as a regression signal on its own.

## Running the C++ side (not verified here)

On a Linux machine/CI runner with the dependencies from
`third_party/libaddressinput/cpp/README.md`:

```bash
sudo apt-get install gyp ninja-build libgtest-dev python3 libre2-dev
cd third_party/libaddressinput/cpp
gyp --depth=. libaddressinput.gyp
ninja -C out/Default
```

That gets you upstream's test binaries, but *not* a corpus-driven emitter —
upstream doesn't ship one. You'd need to write a small `main.cc` (using
`AddressData`, `GetFormattedNationalAddress`, `AddressValidator`,
`BuildComponents` directly, the same way `cpp/test/*_test.cc` does) that
reads `corpus.json`-shaped input and writes JSON matching `js-output.json`'s
shape, then diff the two. This is the piece that's still open — see
`.planning/PLAN.md`'s Phase 8 progress notes.
